# Boostix 1.9.4 BETA

Boostix 1.9.4 устраняет несколько конкретных причин отказа установки и
обновления, улучшает восстановление legacy-версий и исправляет масштабирование
интерфейса. Это предварительный выпуск, а не заявление о совместимости с любым
компьютером или корпоративной сетью.

## Что исправлено

- переход с версий 1.3–1.8 сохраняет тип предыдущей установки; при неуспешной
  проверке запуска восстанавливаются прежние legacy-файлы и регистрация, затем
  запускается прежнее приложение;
- недоступный, отсутствующий или перенаправленный системный каталог
  необязательного ярлыка больше не должен отменять основную установку; причина
  сохраняется в `setup-<correlation>.log`;
- повреждённый или wrong-identity предыдущий EXE не запускается как цель отката;
  вместо этого используется транзакционный repair;
- recovery watchdog больше не удерживает `UpdateRollback` как текущий каталог,
  поэтому немедленный uninstall/cleanup после обновления не должен получать
  ложную ошибку «каталог используется другим процессом»;
- нехватка места, запрет записи в `%TEMP%` и локальная блокировка файла больше не
  показываются как общая проблема с интернетом;
- updater выполняет best-effort preflight свободного места на обычном томе
  `%TEMP%`; redirected/quota/network пути окончательно проверяются реальным
  созданием защищённого каталога и записью в удерживаемый файл;
- повтор загрузки ограничен временными сетевыми ошибками; неверные размер,
  SHA-256 или PE-структура приводят к проверке следующего разрешённого источника
  и затем к безопасному отказу;
- повреждённый HTTP 200 ответ GitHub repository ref, например HTML от captive
  portal или proxy, переводит проверку на RSA-проверяемый signed-main fallback;
- основное окно сохраняет резкий layout на 1920×1080 при масштабе до 200%, а
  установщик и окно обновления масштабируют собственные контролы и индикатор
  прогресса по активному DPI;
- анимации учитывают системную настройку Reduced Motion; уточнены клавиатурный
  focus cue и контраст малого акцентного текста;
- elevated installer до запуска основной логики ограничивает нативный DLL search
  каталогом System32 и безопасно отказывает, если включить эту политику нельзя;
- setup-журнал стал уникальным для каждого запуска:
  `%ProgramData%\Boostix\Logs\setup-<correlation>.log`. Каталог защищён ACL и
  проверяется на reparse point, fallback в `%TEMP%` удалён, сырые аргументы не
  записываются;
- elevated health probe больше не читает пользовательские preferences/legacy
  markers и не пишет `update.log` или `crash.log` в LocalAppData: проверка
  использует только in-memory компоненты, а результат фиксирует установщик;
- посторонний каталог с невалидным именем в защищённом `UpdateRollback`
  журналируется и остаётся нетронутым, но не блокирует все установки. Валидно
  названное повреждённое состояние по-прежнему останавливает операцию fail-closed.

## Проверки выпуска

В исходный код включены автоматические регрессии для legacy rollback,
повреждённой установки, классификации ошибок updater, DPI 100–200%, ширины
индикатора прогресса, клавиатурного фокуса и Reduced Motion. Финальный локальный
набор выполнил 30 из 30 обязательных тестов; offline-canary подписанного канала и
проверка Microsoft Defender также завершились успешно. Публикация должна
выполняться только после зелёного обязательного CI из чистого checkout и
отдельной проверки публичного update-канала. Автоматические контракты не заменяют
незавершённую VM- и физическую приёмку.

## Известные ограничения

- целевая среда beta — Windows 10/11 x64, интерактивный UAC и стандартная
  установка в `%ProgramFiles%\Boostix`;
- EXE пока не имеют доверенной Authenticode-подписи. SmartScreen, WDAC,
  AppLocker, антивирус или EDR могут показать неизвестного издателя либо
  полностью заблокировать запуск;
- независимого бинарного CDN нет: EXE загружается только через GitHub raw или
  GitHub Release. jsDelivr используется только для небольшого подписанного
  манифеста;
- старые клиенты 1.3–1.8 не имеют всех транспортных исправлений 1.9.4. Если
  доступный им endpoint заблокирован, потребуется официальный versioned
  installer с ручной сверкой SHA-256;
- 120-секундный post-install health-check применяется к update/legacy migration
  при пригодном предыдущем EXE. Чистая установка и repair повреждённого EXE
  используют атомарную транзакцию, но не тот же post-launch health rollback;
- предварительная оценка свободного места не может заранее определить каждую
  пользовательскую quota или фактическую вместимость redirected/network
  `%TEMP%`; окончательный held-file write может отказать позже и должен оставить
  текущую установку неизменной;
- Windows ARM64, SYSTEM/session 0, реальные Basic/NTLM/Negotiate proxy,
  корпоративная TLS inspection, EDR-блокировки и полная mixed-DPI/accessibility
  матрица ещё не подтверждены;
- гарантированный прирост FPS не заявляется.

Не отключайте SmartScreen, антивирус, UAC, TLS-проверку или корпоративные
правила ради установки. Полный перечень ограничений находится в
[`docs/KNOWN-ISSUES.md`](docs/KNOWN-ISSUES.md), инструкции диагностики — в
[`TROUBLESHOOTING.md`](TROUBLESHOOTING.md).

## Артефакты

- `Boostix-Setup-1.9.4.exe` — основной versioned installer;
- `Boostix-Setup-Latest.exe` — latest-копия того же проверенного выпуска;
- `MajesticBoost-Setup-1.9.4.exe` — только транспортный мост для старых
  установок;
- `SHA256SUMS.txt` — опубликованные контрольные суммы.

Перед запуском сравните SHA-256 скачанного файла с `SHA256SUMS.txt`. RSA-подпись
манифеста защищает метаданные update-канала, но не заменяет Authenticode-подпись
издателя Windows.
