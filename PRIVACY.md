# Конфиденциальность Boostix

Дата редакции: 2 августа 2026 года.

Boostix работает локально. В приложении нет учётных записей, рекламы,
аналитических SDK, удалённой телеметрии или автоматической отправки
диагностических данных разработчику.

## Какие данные обрабатываются локально

Для диагностики и управления сессией Boostix может читать:

- версию Windows и сведения об оборудовании;
- объём физической и доступной памяти, commit, файл подкачки и системный кэш;
- сведения о видеоадаптерах и видеопамяти, если Windows их предоставляет;
- свободное место на диске и текущий план питания;
- наличие и состояние выбранных пользователем фоновых процессов;
- локальные записи Windows Event Log, относящиеся к недавнему сбою отслеживаемого
  процесса;
- результаты локального измерения времени кадров;
- состояние изменений, необходимое для безопасного восстановления Windows.

Эти данные используются на устройстве пользователя. Они не отправляются
разработчику автоматически.

Elevated installer записывает диагностику в отдельный файл
`%ProgramData%\Boostix\Logs\setup-<correlation>.log` для каждого запуска.
Каталог защищён ACL и проверяется на reparse point; fallback в пользовательский
`%TEMP%` не используется. В журнал попадают нормализованный режим запуска и
число аргументов, но не сырые значения командной строки. Журнал может содержать
SID, версии среды, этап операции и обезличиваемые тексты ошибок, поэтому перед
отправкой его всё равно нужно просмотреть.

Elevated health probe не дописывает `%LOCALAPPDATA%\Boostix\update.log`. Он
обменивается одноразовым сигналом через защищённую транзакцию в ProgramData, а
результат проверки фиксирует родительский установщик в своём setup-журнале.

## Сетевые обращения

При запуске Boostix выполняет исходящие HTTPS GET-запросы к GitHub для проверки
обновления. Если основной GitHub-канал манифеста недоступен, приложение может
запросить резервную пару manifest/signature у jsDelivr. Исполняемый установщик
загружается только с GitHub raw или GitHub Release и только по решению
пользователя. Проверяются подпись манифеста, версия, размер и SHA-256 файла.

GitHub и, при использовании резервного манифеста, jsDelivr как сетевые операторы
могут видеть IP-адрес, время запроса, User-Agent и стандартные технические данные
соединения. Обработка GitHub регулируется
[политикой конфиденциальности GitHub](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement).
Boostix не добавляет к запросу имя пользователя, адрес электронной почты или
идентификатор устройства.

Кроме перечисленных запросов канала обновлений, других автоматических сетевых
передач данных приложение не выполняет.

## Локальные файлы и срок хранения

Данные приложения находятся в его каталоге внутри `%LOCALAPPDATA%`. Защищённое
состояние восстановления и временные файлы измерений могут находиться в
каталоге приложения внутри `%PROGRAMDATA%`.

Текущие ограничения хранения:

- не более 20 отчётов о завершённых сессиях; интерфейс показывает 10 последних;
- не более 20 сохранённых файлов измерения времени кадров;
- основной журнал сбоев ротируется при размере 512 КиБ, хранится одна предыдущая
  копия;
- журнал подготовки сессии заменяется при следующем полном запуске подготовки,
  но может дополняться в течение активной сессии;
- журнал обновления, настройки пользователя и последний отчёт сохраняются до
  удаления приложения или ручного удаления данных;
- отдельные setup-журналы сохраняются в `%ProgramData%\Boostix\Logs` до удаления
  соответствующих локальных данных; каждый файл ротируется при размере 2 МиБ и
  может иметь одну копию `.previous`;
- резервная копия системных изменений хранится до успешного восстановления.

Нельзя вручную удалять защищённое состояние восстановления до возврата Windows
в исходное состояние.

## Экспорт диагностики

Экспорт создаётся только после явного действия пользователя и сохраняется в
выбранный им файл. Перед экспортом Boostix ограничивает объём отчёта и удаляет
или заменяет известные персональные пути и чувствительные фрагменты.

Автоматическое обезличивание не может гарантировать удаление каждого
непредусмотренного значения. Перед отправкой отчёта пользователь должен открыть
его как текст и проверить содержимое. Не публикуйте необработанные журналы,
дампы памяти, токены или полные пути к личным документам.

## Управление и удаление данных

- Историю и журналы можно удалить вместе с локальными данными приложения после
  завершения всех операций восстановления.
- Деинсталлятор должен сначала предложить восстановить системные изменения и
  только затем удалять данные.
- Пользователь может заблокировать сетевой доступ Boostix средствами Windows;
  основная локальная работа сохранится, а проверка обновлений будет недоступна.

## Изменения политики

При добавлении добровольной отправки отчётов, аналитики или другого сетевого
сервиса эта политика должна быть обновлена до выпуска такой версии. Любая
телеметрия должна быть выключена по умолчанию и включаться только отдельным
информированным согласием.
