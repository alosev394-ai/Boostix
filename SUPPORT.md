# Поддержка Boostix

Текущая тестируемая версия — **2.0.0 BETA**. Целевая среда — Windows 10/11 x64
с интерактивным UAC и стандартной установкой в Program Files. Установка на любой
конфигурации пока не гарантируется.

## Перед обращением

1. Установите последнюю поддерживаемую версию Boostix.
2. Перезагрузите Windows, если приложение сообщает о незавершённой операции.
3. Повторите проблему один раз и запишите точное время.
4. Откройте встроенный центр диагностики и экспортируйте отчёт.
5. Просмотрите отчёт как текст и удалите данные, которыми не хотите делиться.
6. Проверьте известные решения в
   [`TROUBLESHOOTING.md`](TROUBLESHOOTING.md).

## Куда обращаться

Для обычной ошибки или предложения создайте GitHub Issue. Для уязвимости
используйте только приватный канал из [`SECURITY.md`](SECURITY.md).

В обращении укажите:

- версию Boostix и канал (`stable`, `beta` или `RC`);
- исходную установленную версию, если ошибка возникла при обновлении;
- редакцию, версию и номер сборки Windows;
- CPU, GPU, объём RAM и режим файла подкачки;
- тип учётной записи: администратор или обычный пользователь;
- последовательность действий;
- ожидаемый и фактический результат;
- воспроизводится ли проблема после перезагрузки;
- точное время ошибки и идентификатор операции, если он показан;
- точный текст ошибки;
- обезличенный диагностический экспорт.

Снимок экрана полезен для ошибок расположения элементов. Для проблем
масштабирования дополнительно укажите разрешение каждого монитора, масштаб
Windows и монитор, на котором открыто окно.

## Ошибка установки или обновления

Версия 2.0.0 содержит транспортный мост для перехода с установок 1.3–1.9,
системный proxy, ограниченные повторы загрузки, два проверяемых GitHub-источника
EXE и jsDelivr-зеркало только для подписанного манифеста. Это повышает
устойчивость, но не означает поддержку любой сети: корпоративная TLS-инспекция,
нестандартная proxy-аутентификация, WDAC или иная политика организации всё ещё
могут остановить обновление.

Наличие обновления в jsDelivr-манифесте не означает, что EXE доступен: бинарные
файлы загружаются только через GitHub raw или GitHub Release. Независимого
бинарного CDN в 2.0.0 нет. Старым клиентам 1.3–1.9 при блокировке доступного им
endpoint может потребоваться официальный versioned installer и ручная сверка
SHA-256.

Если установка не завершилась:

1. Не запускайте установщик многократно одновременно и дождитесь завершения
   текущего окна UAC.
2. Запишите исходную версию, точное время, этап и полный текст ошибки.
3. В `%ProgramData%\Boostix\Logs` найдите созданный во время ошибки файл
   `setup-<correlation>.log`. Каждый запуск имеет отдельный идентификатор. Если
   защищённый журнал создать не удалось, установщик сообщает, что файловое
   журналирование отключено; fallback в `%TEMP%` отсутствует.
4. Скопируйте только фрагмент вокруг времени ошибки, предварительно удалив SID,
   личные пути и другие чувствительные данные.
5. Укажите, используется ли proxy/VPN, корпоративный антивирус, WDAC или
   подтверждение UAC другой администраторской учётной записью.
6. Если установщик сообщил, что не смог безопасно подготовить запуск, DLL-search
   hardening завершился до инициализации журнала. Обновите Windows штатным
   способом и приложите снимок сообщения; не подменяйте системные DLL и не
   ослабляйте эту проверку.

Ориентируйтесь на категорию сообщения:

- ошибка **локальной записи** — проверьте свободное место на системном диске и
  в `%TEMP%`, quota, права на `%TEMP%` и блокировку файла антивирусом/EDR.
  Предварительная проверка места является best-effort: redirected, quota-backed
  или сетевой `%TEMP%` окончательно проверяется только фактической записью;
- ошибка **сети** — проверьте доступ отдельно к GitHub API,
  `raw.githubusercontent.com` и GitHub Release assets; открытая страница GitHub
  или доступный jsDelivr-манифест не подтверждают доступность EXE;
- ошибка **целостности, подписи, размера, SHA-256, версии или ProductName** — не
  отключайте проверку и не повторяйте запуск непроверенного файла. Скачайте
  официальный versioned installer и сравните его с опубликованным
  `SHA256SUMS.txt`.

Если программа установилась, но ярлык отсутствует, сначала проверьте наличие
`%ProgramFiles%\Boostix\Boostix.exe` и соответствующий `setup-*.log`.
Недоступный или безопасно отклонённый системный каталог ярлыка считается
необязательной деградацией, а не сам по себе признаком неуспешной установки.

При сбое перехода с 1.3–1.9 дополнительно сохраните исходную версию,
`%LOCALAPPDATA%\Boostix\update.log` инициировавшего обновление клиента,
родительский `setup-<correlation>.log` и `recovery.log` из активного каталога
`%ProgramData%\Boostix\UpdateRollback\<идентификатор>`. Elevated health probe
намеренно не дописывает пользовательский `update.log`; итог handshake или
отката находится в setup-журнале. Не удаляйте транзакцию до завершения
восстановления или сохранения диагностики.

EXE 2.0.0 BETA пока не имеют доверенной Authenticode-подписи. Предупреждение о
неизвестном издателе или блокировка политикой Windows — известное ограничение и
блокер stable-релиза. Не отключайте SmartScreen, антивирус, UAC или корпоративные
правила ради установки; приложите точный текст блокировки к обращению.

## Session Guard, Proof Mode и Crash Assistant

Для ошибки определения цели приложите имя EXE, полный путь, время запуска и
укажите, перезапускался ли процесс во время сессии. Не присылайте дамп памяти.

Если Session Guard предупреждает о памяти, сохраните значения доступной
физической RAM, commit reserve, pagefile и памяти цели. Boostix намеренно не
очищает standby list и не уменьшает working set игры, поэтому отсутствие
мгновенного уменьшения общей занятой RAM не является неисправностью.

Для спорного результата Proof Mode сохраните все четыре этапа и подтвердите, что
сцена, настройки, разрешение и ограничитель кадров не менялись. Один прогон или
измерения разных сцен нельзя сравнивать как доказательство эффекта Boost.

Crash Assistant показывает только близкие по времени свидетельства Windows.
Приложите код выхода и обезличенный текст WER/Application Error. Отсутствие
события не доказывает отсутствие сбоя, а найденное событие не доказывает его
первопричину.

Если после сессии остался другой план питания, сначала проверьте, не переключил
ли его пользователь, OEM-утилита или Windows. Boostix не должен перезаписывать
такое внешнее изменение. В обращении укажите питание от сети/батареи и GUID
планов до, во время и после сессии.

## Чего не следует публиковать

- пароли, токены и приватные ключи;
- полный дамп памяти;
- необработанные журналы без проверки;
- полные личные пути, email и имена учётных записей;
- резервную копию системного восстановления;
- чужие документы и конфигурации.

## Границы поддержки

Boostix не гарантирует определённое увеличение FPS. Результат зависит от
оборудования, драйверов, температуры, настроек Windows и нагрузки. Поддержка не
включает обход антивируса, UAC, anti-cheat или ограничений стороннего ПО.

ARM64, запуск из SYSTEM/session 0, все виды proxy-аутентификации и полный набор
сценариев UAC ещё не подтверждены E2E-тестами. Такие отчёты принимаются как
проблемы совместимости, но без обещания немедленного универсального исправления.

Не изменяйте вручную защищённое состояние восстановления. Если откат не
завершён, сохраните резервную копию и приложите обезличенную диагностику.
