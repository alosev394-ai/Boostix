# История изменений Boostix

## 2.0.0 BETA — 2026-08-12

### Сессия и точная цель

- Добавлен выбор точного целевого процесса по PID, времени запуска и полному
  пути с защитой от повторного использования PID.
- Добавлен Session Guard для наблюдения за физической памятью, commit reserve,
  файлом подкачки и памятью точной цели. Единичные всплески фильтруются
  гистерезисом и cooldown.
- Временный приоритет применяется только к закреплённой цели на переднем плане и
  восстанавливается после сессии.
- Добавлен безопасный план питания на сессию: только при питании от сети, с
  восстановлением точного предыдущего GUID и сохранением внешнего переключения.

### Измерение и диагностика

- Добавлен Proof Mode из четырёх 60-секундных прогонов по схеме
  Baseline → Boost → Boost → Baseline с закреплённым контекстом и атомарной
  контрольной точкой.
- Отчёт Proof Mode показывает FPS, 1% low, P95 и вариативность, но не заявляет
  результатом универсальный прирост производительности.
- Добавлен evidence-only Crash Assistant: завершение отслеживается для точного
  процесса, а ограниченные по времени WER/Application Error события показываются
  как корреляция, а не доказанная первопричина.
- Добавлена read-only оценка Background Impact. Явно выбранные приложения
  получают только штатный запрос на закрытие; force-kill не применяется.

### Безопасность и надёжность

- Удалены активные сценарии очистки standby list, working-set trim целевого
  приложения, принудительного GC и принудительного завершения фоновых процессов.
- Усилен updater/installer для сетевых и локальных отказов: системный proxy,
  TLS/redirect, ограниченные retry, неизвестная длина ответа, нехватка места,
  временная блокировка файлов, отмена UAC, health handshake и rollback.
- Сохранена миграция установленных версий 1.3–1.9 через совместимый legacy-мост;
  криптографические проверки и идентичность продукта не ослабляются.
- Версия остаётся BETA prerelease: публичные EXE пока не имеют доверенной
  Authenticode-подписи и полная VM/lifecycle-матрица ещё не завершена.

Подробности: [`release-notes-2.0.0.md`](release-notes-2.0.0.md).

## 1.9.4 BETA — 2026-08-02

### Установка, обновление и восстановление

- Исправлена обнаруженная причина сбоя чистой установки: резервная копия
  регистрации теперь корректно учитывает ещё не созданную папку Boostix в
  общем меню «Пуск».
- Переход со старых версий 1.3–1.8 теперь сохраняет тип предыдущей установки в
  защищённом состоянии отката. При неуспешной проверке запуска восстанавливаются
  именно прежние legacy-файлы и регистрация, после чего запускается прежнее
  приложение. Состояние старого формата остаётся читаемым.
- Если Windows не предоставляет безопасный общий рабочий стол или каталог
  «Пуск», либо этот необязательный путь недоступен или перенаправлен, установщик
  записывает причину в журнал и пропускает соответствующий ярлык. Основные файлы
  программы продолжают устанавливаться. Для управляемых каталогов установки,
  обновления и отката junction, symlink и другие reparse point по-прежнему
  отклоняются до изменения данных.
- Повреждённый предыдущий EXE или файл с неожиданными метаданными продукта не
  запускается как цель отката. Вместо этого выполняется транзакционное
  восстановление файлов и регистрации без попытки исполнить такой файл.
- Recovery watchdog и его self-delete helper запускаются из System32, поэтому
  защищённый `UpdateRollback` больше не остаётся их текущим каталогом и не
  мешает немедленному удалению либо следующей установке. E2E-cleanup получил
  ограниченный retry для короткой блокировки файла антивирусом/Windows.
- Ошибки свободного места, доступа к `%TEMP%`, локальной записи и блокировки
  файла антивирусом больше не маскируются сообщением о проблеме с интернетом.
  Повтор загрузки выполняется только для временных сетевых ошибок.
- Перед загрузкой updater выполняет best-effort проверку свободного места на
  томе `%TEMP%`. Для redirected, quota-backed или сетевого `%TEMP%` эта оценка
  может быть недоступна, поэтому окончательным доказательством остаются создание
  защищённого каталога и реальная запись в удерживаемый файл.
- Детерминированная ошибка размера, SHA-256 или структуры PE не вызывает
  повторную загрузку того же неизменяемого адреса. Проверяется следующий
  разрешённый источник, после чего пакет безопасно отклоняется как не прошедший
  проверку целостности.
- Если GitHub API возвращает HTTP 200 с повреждённым или подменённым proxy
  содержимым вместо repository ref, клиент переходит к RSA-проверяемому
  signed-main манифесту. Ослабления подписи, SHA-256 или allowlist нет.
- Elevated installer до инициализации журнала и WinForms ограничивает нативный
  DLL search системным каталогом Windows. Если безопасный режим поиска включить
  нельзя, установка завершается до выполнения основной операции.
- Каждый elevated-запуск создаёт отдельный журнал
  `%ProgramData%\Boostix\Logs\setup-<correlation>.log` в ACL-защищённом каталоге
  без reparse point. Fallback в пользовательский `%TEMP%` удалён; сырые аргументы
  командной строки не записываются, сохраняются только нормализованный режим и
  их количество.
- Elevated health probe больше не читает пользовательские preferences/legacy
  markers и не пишет `update.log` либо `crash.log` в LocalAppData. Он использует
  только in-memory проверку готовности; результат handshake, тайм-аут или причина
  отката фиксируются родительским установщиком в защищённом setup-журнале.
- Посторонний каталог с невалидным именем внутри защищённого `UpdateRollback`
  журналируется и остаётся нетронутым, но больше не блокирует все последующие
  установки. Валидно названная повреждённая транзакция по-прежнему приводит к
  fail-closed остановке, чтобы не потерять возможность отката.

### Интерфейс и автоматические проверки

- Для основного окна добавлен компактный layout 460×492 DIP на рабочей области
  1920×1080 при масштабе 200% без дробного масштабирования содержимого. Контракты
  100%, 125% и 150% сохранены.
- Установщик и окно обновления используют DPI-масштабирование для геометрии
  кнопок, переключателей, рамок и индикатора прогресса на 125–200%. Кнопка
  закрытия после масштабирования привязывается к фактической правой границе,
  включая случай ограничения окна рабочей областью Windows.
- Анимации основного приложения и установщика учитывают системную настройку
  Reduced Motion. Малый акцентный текст проверяется на контраст, а видимый
  focus cue показывается только при клавиатурной навигации.
- Добавлены автоматические регрессии legacy-миграции, восстановления повреждённой
  установки, DPI, ширины индикатора прогресса, фокуса и Reduced Motion. Эти
  проверки не заменяют незавершённую ручную и VM-приёмку.
- Реальный install → repair/update → uninstall E2E запускается на чистом
  одноразовом Windows runner до UI-тестов, чтобы тестовые пользовательские
  данные не маскировали состояние нового компьютера.
- Публичная canary больше не считает успешный PowerShell-сценарий ошибкой из-за
  незаданного `$LASTEXITCODE`; закреплённые GitHub Actions обновлены на версии с
  Node.js 24.
- При сбое lifecycle E2E журнал установщика сохраняется в выводе до безопасной
  очистки одноразовой машины, поэтому следующая причина отказа не теряется.

## 1.9.3 BETA — 2026-08-02

### Проверяемые источники установщика

- Удалён неработающий путь загрузки EXE через jsDelivr: публичная проверка
  подтвердила ответ `403` для бинарного файла.
- Установщик теперь загружается только с двух реально проверяемых адресов:
  GitHub raw и GitHub Release. jsDelivr используется только для небольшого
  подписанного манифеста, который сервис отдаёт корректно.
- Публичная canary-проверка больше не имитирует недоступный бинарный CDN и
  требует успешную загрузку обоих заявленных GitHub-источников.

## 1.9.2 BETA — 2026-08-02

### Надёжность резервного канала

- Зеркало подписанного манифеста переведено с кэшируемой до 12 часов ветки
  jsDelivr `@main` на обновляемый semver-псевдоним `@latest`.
- Публичная canary-проверка закрепляет тот же адрес и требует полного совпадения
  RSA-подписи и байтов манифеста между GitHub raw и jsDelivr.
- Версия выпущена отдельно от 1.9.1: уже опубликованный тег и его файлы не
  переписывались, поэтому проверяемые SHA-256 остаются неизменными.

## 1.9.1 BETA — 2026-08-02

### Установка и обновление

- Восстановлен совместимый канал обновления для установленных версий 1.3–1.8:
  подписанный `update.json` снова описывает legacy-мост, а `update-v2.json`
  одновременно публикует legacy- и основной Boostix-пакеты.
- Legacy-мост теперь содержит канонический установщик Boostix и передаёт его в
  установленный `Uninstall.exe`. Строгая проверка `ProductName`, версии, размера
  и SHA-256 не ослаблялась.
- Загрузка использует системный proxy с учётными данными Windows, ограниченные
  повторы с паузой и разрешённые резервные источники: GitHub raw, GitHub Releases
  и jsDelivr. Любая ошибка RSA-подписи, SHA-256, размера, версии или разрешённого
  URL по-прежнему блокирует установку.
- Пакет обновления сохраняется во временный каталог с защищённым ACL, доступным
  текущему пользователю, Administrators и SYSTEM, поэтому повышенный процесс
  может прочитать уже проверенный файл без открытия каталога другим
  пользователям.
- Проверка новой версии после установки сокращена до минимального handshake и
  ожидает готовность до 120 секунд. Она не требует показа полного интерфейса или
  прохождения диагностик.
- Для временно занятых файлов добавлены ограниченные повторы атомарной замены и
  восстановления вместо немедленного отказа.
- Ярлыки создаются через нативный Windows Shell Link API без зависимости от
  Windows Script Host. Ярлык рабочего стола помещается в общий рабочий стол
  Windows, что устраняет смешивание профилей при подтверждении UAC другой
  администраторской учётной записью.
- Установщик ведёт локальный журнал `%ProgramData%\Boostix\Logs\setup.log`; если
  этот каталог недоступен, используется `%TEMP%\Boostix-Setup.log`.

### Сборка и безопасность релиза

- CI и проверки канала обновлений больше не привязаны к номеру предыдущей
  версии; версия артефактов читается из сборки.
- Внешние GitHub Actions закреплены по commit SHA, а проверка контрактов подписи
  и очистка чувствительных данных ключа усилены.
- Обязательный CI выполняет чистую сборку и регрессионный набор на
  `windows-2022` и `windows-2025`, а на одноразовых GitHub-hosted runner отдельно
  проходит реальный цикл legacy install → repair/update → uninstall.
- Добавлен независимый публичный canary: каждые шесть часов он без запуска EXE
  скачивает подписанные основной и legacy-манифесты и все разрешённые копии
  установщиков, затем сверяет RSA, SHA-256, размер и Windows-метаданные.
- Локальный обязательный набор расширен кросс-машинными, signing/CI и
  installer/update-контрактами; перед публикацией 1.9.1 он проходит полностью.
- RSA-подпись манифеста защищает метаданные обновления, но EXE 1.9.1 пока не
  подписаны доверенным Authenticode-сертификатом. Это известный блокер выпуска
  stable: Windows SmartScreen, WDAC или корпоративная политика могут не разрешить
  установку.
- Полная матрица установки и обновления на Windows 10/11 x64, ARM64, в
  корпоративных proxy-сетях и в нестандартных UAC-сценариях ещё не завершена.
  Универсальная установка на любом компьютере в этой beta не заявляется.

## 1.9.0 BETA — 2026-07-29

### Бренд и интерфейс

- Продукт полностью переименован в Boostix.
- Основной экран упрощён до единого заголовка `BOOSTIX`.
- Акцентная палитра заменена на фиолетовую; опасные действия остаются красными.
- Используются системные шрифты Windows без извлечения ресурсов сторонних
  приложений.
- Уточнены отступы, DPI-поведение, клавиатурный фокус, AutomationName и
  AutomationId.

### Независимая работа

- Удалены обнаружение и автоматический запуск стороннего лаунчера.
- Новая сессия не изменяет конфигурации конкретной игры или сервиса.
- Приоритет временно повышается только для крупного активного окна и
  восстанавливается после завершения Boost.
- Закрытие сторонних приложений стало строго opt-in и сначала выполняется
  штатным способом.
- HAGS больше не переключается универсальным профилем: Boostix сохраняет
  пользовательское значение, пока эффект не подтверждён для конкретной
  комбинации Windows, драйвера и GPU.

### Корректность и честность

- `1% low` считается как FPS по среднему времени худшего 1% кадров.
- P99 frame time показывается отдельно.
- Сравнение двух запусков доступно только при совпадении явного контекста.
- Обслуживание памяти уменьшает только working set самого Boostix; системный
  standby-кэш и память других процессов не затрагиваются.
- Диагностика различает физическую память, commit, pagefile и VRAM.

### Безопасность и надёжность

- Elevated-деинсталлятор ограничен allowlist-каталогами и блокирует junction,
  symlink и другие reparse point на каждом уровне пути.
- Удаление повторно проверяет canonical path непосредственно перед операцией.
- Добавлены атакующие тесты удаления и единый обязательный тестовый runner.
- Добавлен Windows CI с чистой сборкой и запретом пропуска тестов.
- Подготовлены документы по безопасности, конфиденциальности, поддержке,
  тестовой матрице и выпуску.

### Обновления и установка

- Имена приложения, установщика, ярлыков и локальных каталогов переведены на
  Boostix.
- Сохранена ограниченная совместимость с legacy-установками для безопасного
  обновления и восстановления.
- Подписанный manifest v1 получил отдельную тройку `boostixInstallerUrl`,
  `boostixSha256`, `boostixSize`; временный транспортный мост с тем же payload
  Boostix позволяет версиям 1.8.x перейти на 1.9.0 без ослабления
  RSA/SHA-256-проверок.
- Укреплены проверки update-пакета и атомарный rollback.

История более ранних предварительных сборок остаётся доступна в Git.
