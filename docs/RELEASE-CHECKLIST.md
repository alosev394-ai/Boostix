# Чек-лист релиза Boostix 2.0.0

2.0.0 может публиковаться только как **BETA prerelease**, пока отсутствует
доверенная Authenticode-подпись и не завершена полная внешняя lifecycle-матрица.
Локальный зелёный тест не заменяет проверку финального публичного артефакта.

## 1. Заморозка версии

- [ ] `ProductBrand.ProductVersion` равен `2.0.0`, assembly version — `2.0.0.0`.
- [ ] Оба `app.manifest` содержат `2.0.0.0`, PerMonitorV2 и ожидаемый execution
  level.
- [ ] ProductName — `Boostix`, CompanyName/Publisher — `Silas Suspect`, метка —
  `BETA`.
- [ ] Имена основных артефактов содержат `2.0.0`; legacy-имя используется только
  транспортным мостом.
- [ ] `README.md`, `CHANGELOG.md`, `release-notes-2.0.0.md`, support/security и
  known issues описывают фактическое поведение одной и той же ревизии.
- [ ] Нет обещаний гарантированного FPS или универсальной совместимости.
- [ ] Release commit/tag зафиксирован; рабочее дерево чистое.

## 2. Автоматические проверки

- [ ] `build.ps1` выполнен из чистого checkout.
- [ ] `tests\Run-All.ps1` завершён без ошибок и без пропущенного обязательного
  `Test-*.ps1`.
- [ ] Все тесты использовали только что собранные артефакты, а не установленную
  ранее версию.
- [ ] `git diff --check` не находит ошибок пробелов/окончаний строк.
- [ ] CodeQL и обязательные GitHub Actions зелёные для точного release commit.
- [ ] Три последовательных чистых CI-прогона зелёные перед stable; для BETA
  отклонение документируется и блокирует публикацию, если затрагивает
  безопасность, установку, rollback или данные.

## 3. Точная цель и Session Guard

- [ ] Цель подтверждается PID + временем запуска + полным путём.
- [ ] PID reuse и перезапуск процесса не принимаются как прежняя сессия.
- [ ] После выбора цель не зависит от наличия видимого окна.
- [ ] Foreground-priority меняется только у точной цели и возвращается к
  исходному значению.
- [ ] Session Guard различает физическую память, commit reserve, pagefile и
  память цели.
- [ ] Один всплеск не создаёт critical-событие; подтверждены hysteresis и
  cooldown.
- [ ] Нулевой commit reserve не переписывается поздним здоровым измерением как
  будто критического события не было.
- [ ] Таймеры, watcher и подписки освобождаются при завершении/отмене сессии.

## 4. Background Impact

- [ ] Анализ по умолчанию read-only и не меняет процессы/систему.
- [ ] Закрытие доступно только после явного выбора пользователя.
- [ ] Используется только graceful close; force-kill отсутствует во всех
  production-путях.
- [ ] Исключения пользователя соблюдаются; повторно открытое приложение не
  закрывается без нового действия.
- [ ] Интерфейс не называет корреляцию фоновой нагрузки доказанным влиянием на
  FPS.

## 5. Proof Mode

- [ ] Порядок строго Baseline → Boost → Boost → Baseline, каждый этап 60 секунд.
- [ ] До каждого capture повторно проверяются PID, start time, путь и
  закреплённый контекст.
- [ ] Неверное состояние Boost или изменившаяся цель блокирует этап.
- [ ] Контрольная точка записывается атомарно и проверяется перед восстановлением.
- [ ] Отмена убирает capture-процесс и временные файлы.
- [ ] Итог строится только после четырёх принятых этапов и показывает средний
  FPS, 1% low, P95 и вариативность.
- [ ] Вывод Positive/Neutral/Negative учитывает разброс пар, а UI не обещает
  универсальный эффект.

## 6. Crash Assistant

- [ ] Exact process watcher проверяет PID, start time и путь до подписки.
- [ ] Фиксируются фактические exit time и exit code.
- [ ] Код выхода 0 не запускает аварийный сценарий.
- [ ] Поиск WER/Application Error ограничен идентичностью и временным окном.
- [ ] Невалидные/устаревшие события отклоняются.
- [ ] UI говорит о свидетельстве/корреляции, а не доказанной причине.

## 7. План питания на сессию

- [ ] Доверенный план создаётся установщиком, но Apply не оставляет его активным
  глобально.
- [ ] Активация выполняется только от сети; батарея означает безопасный skip.
- [ ] Сохраняется точный предыдущий GUID и маркер точной сессии.
- [ ] Завершение Boost восстанавливает предыдущий план только если активен план
  Boostix.
- [ ] Внешнее переключение пользователя/Windows/OEM не перезаписывается.
- [ ] Startup recovery принимает только собственный валидный маркер; reparse
  point, подмена ACL и повреждённый JSON дают fail-safe результат.
- [ ] Restore удаляет только соответствующую доверенную конфигурацию.

## 8. Запрещённые агрессивные действия

- [ ] В production отсутствуют standby-list purge и очистка системного
  файлового кэша.
- [ ] Нет `EmptyWorkingSet`, `SetProcessWorkingSetSize` или другого trim целевой
  программы.
- [ ] Нет принудительного `GC.Collect` ради показного уменьшения памяти.
- [ ] Нет force-kill фоновых приложений.
- [ ] Нет отключения Defender, SmartScreen, UAC, Firewall, signature checks или
  anti-cheat.
- [ ] Нет глобального постоянного выключения power throttling, USB/disk timeout,
  core parking или EPP.

## 9. Установка, обновление и rollback

- [ ] Чистая установка, повторная установка, update, repair и uninstall проходят
  на чистых Windows 10 и 11 VM.
- [ ] UAC cancel, disk full/quota, запрещённый `%TEMP%`, file lock и interruption
  не оставляют частичную установку.
- [ ] Сетевые, локальные, UAC и integrity-ошибки классифицируются раздельно.
- [ ] Проверены TLS, redirect, content length unknown, slow response, 403/404/429,
  5xx, DNS/offline и системный proxy.
- [ ] Manifest RSA, allowlist, размер, SHA-256, PE, версия и ProductName проходят
  fail-closed проверку.
- [ ] Защищённый staging и rollback отклоняют junction/symlink/reparse point и
  выход из allowlist.
- [ ] Health handshake не зависит от видимого окна и имеет ограниченный timeout.
- [ ] Locked-file retry ограничен; после исчерпания выполняется rollback или
  безопасный отказ.
- [ ] Повреждённый/wrong-identity старый EXE не исполняется как rollback target.
- [ ] Обновления 1.3, 1.4, 1.5, 1.6, 1.7, 1.8 и 1.9 → 2.0.0 проверены отдельно;
  при сбое пригодная старая установка восстанавливается.
- [ ] Setup logs создаются в ACL-защищённом ProgramData без небезопасного
  `%TEMP%` fallback и без сырых секретов командной строки.

## 10. UI, DPI и доступность

- [ ] Основное окно, Центр Boost, first-run/update/rollback и installer проверены
  при 100/125/150/175/200% DPI.
- [ ] Проверены 1366×768, 1920×1080, 2560×1440, 3840×2160 и mixed-DPI.
- [ ] Нет обрезанных toggle/scrollbar/progress track, размытого текста и
  перекрытия watermark.
- [ ] Кастомные вкладки дают корректные UIA Tab/Selection patterns и один
  выбранный элемент.
- [ ] Логичный Tab-порядок, Enter/Space/Escape и focus cue работают с клавиатуры.
- [ ] Минимальный обычный текст и интерактивные области соответствуют дизайн-
  токенам; контраст проверен отдельно.
- [ ] High Contrast, Narrator, RDP, reduced motion и Windows text scale 200%
  пройдены вручную.

## 11. Публичный канал

- [ ] Финальные EXE собраны один раз из release commit; их SHA-256 и размер
  зафиксированы до подписи манифеста.
- [ ] Versioned, latest и legacy assets опубликованы атомарно в ожидаемом
  prerelease.
- [ ] `update.json`, `update-v2.json` и подписи относятся к тем же байтам.
- [ ] Live-canary скачал manifest/signature через разрешённые источники и все EXE
  через публичные URL, затем сверил RSA, SHA-256, размер, версию и ProductName.
- [ ] Обновление с реально установленной 1.9.x показывает прогресс, завершение и
  запускает 2.0.0; отказ тестового health handshake возвращает 1.9.x.
- [ ] Текущая рабочая установка не заменялась локально для имитации обновления.

## 12. Решение о публикации

### BETA prerelease

- [ ] Нет открытых P0/P1 по безопасности, путям, update, rollback или потере
  данных.
- [ ] Все автоматические контракты и обязательные VM для prerelease зелёные.
- [ ] Известные неподтверждённые конфигурации перечислены публично.
- [ ] Release помечен как prerelease, а название содержит `2.0.0 BETA`.

### Stable — пока заблокирован

- [ ] EXE подписаны доверенным Authenticode-сертификатом с RFC 3161 timestamp.
- [ ] Windows подтверждает ожидаемого издателя для каждого EXE.
- [ ] Завершена вся [`TEST-MATRIX.md`](TEST-MATRIX.md), включая ARM64-решение,
  proxy/EDR/UAC и accessibility.
- [ ] Не менее 20 физических ПК, 500 часов сессий и 100 полных Boost-сессий.
- [ ] Успешность install/update и crash-free sessions не ниже 99%.
- [ ] 30 дней RC без нового критического дефекта.

Пока любой stable-пункт не подтверждён, метка `BETA` и prerelease обязательны.
